# 02 · 生成提示词

这份文档是"下次让 AI 直接生成一个同类网页"的**提示词模板**。
建议按「先骨架 → 再内容 → 后调优」三段走，比一次性丢一大段效果好很多。

---

## 一、总提示词（一次性生成版，可直接复制）

> 把 `<>` 里的内容替换成你自己的信息。

```text
请用**单个 HTML 文件**做一个像素风（8-bit / FC 游戏质感）的活动引导网页，
用途是：<活动名称，例如：2026 社团迎新大会>，主要投屏在会场大屏上给观众看，
手机和电脑浏览器都要能正常打开。

【整体气质】
- 像素风，硬边、无抗锯齿：全局禁用字体平滑，画布用 image-rendering:pixelated。
- 配色：<例如：奶油纸张底 + 蓝绿天光 + 木色描边 + 金色点缀>，整体明亮、干净、不土。
- 界面像一台老游戏的菜单：左上角一个"玩家状态栏"，中间是各个画面，按钮做成像素凸起块。
- 所有像素图形必须用代码画（canvas fillRect / 字符地图），不要引用任何图片素材。

【页面与流程】
1. 启动页：像素进度条 + 几行载入日志，跑完自动进封面。
2. 封面：一整幅程序化像素场景（天空渐变、远景天际线、中景建筑、中央主楼、树、草坪、栅栏、花），
   上方叠标题与一个 START 按钮，提示"或按 Enter 开始"。
   草坪上要有十几个像素小人，各做各的动作（<列举：敲代码、看手机、喝奶茶、打球、远程遥控……>）。
3. 大会流程：以"任务板"形式列出 <N> 个环节卡片（编号 + 图标 + 名称 + 英文标签 + 完成状态），
   顶部有"已完成 n/总数"进度条。
4. 环节详情：弹窗展示该环节的介绍、要点列表、时长/形式等信息块，底部可"标记完成"。
5. 其中<某几个环节>要有独立整页：
   - 才艺展示：节目卡片列表，点进去是每位表演者的单独整页（大字姓名 + 大号像素人物 + 描述），
     底部可切换上一位/下一位。
   - 协会/团队介绍：一段介绍文字 + 理念标签 + 业务领域 + 部门/小组卡片。
   - 趣味游戏：<4> 个小游戏，每个都要有玩法说明和一个**能现场点的演示区**
     （例如"看 emoji 猜成语，可揭晓答案并切题"）。
6. 结语页："谢谢观看" + 组织落款 + 完成度统计 + 重新开始。

【交互与细节】
- 支持键盘：Enter 确认/开始、Esc 返回、左右方向键切换同类内容、M 关音效、R 重置进度。
- 完成状态存 localStorage，刷新后仍在。
- 音效用 WebAudio 现场合成的方波短音，不要引入音频文件。
- 封面小人要能**用鼠标拖动换位置**，并且**点一下会弹出语言气泡说一句话**（台词可配置）。
- 像素中文字体：预留一个 @font-face 占位（构建时内联字体文件），字体没加载时回退到系统黑体。
- 所有文案、环节、人物、游戏数据集中放在文件顶部一个配置对象里，方便我以后改内容。
- 代码里加必要的中文注释，方便非程序员改动。

【产出要求】
- 一个能直接双击打开的 HTML 文件，除字体文件外不依赖任何外部资源。
- 画布按窗口宽度自适应缩放，窄屏（手机竖屏）时自动减少小人和卡片列数。
- 完成后列出：文件结构、配置对象各字段的含义、以及"想改 X 该改哪里"的对照表。
```

## 二、分段提示词（推荐，效果更稳）

一次性丢一大段，AI 容易在某一块偷懒。分成三段更可控：

### 第 1 段 · 只要骨架

```text
用单个 HTML 文件搭一个像素风活动网页的**骨架**，先不要填具体内容：
- 定义好各个"画面"（启动页 / 封面 / 流程板 / 环节弹窗 / 才艺展示 / 单人页 /
  介绍页 / 游戏列表 / 单个游戏 / 结语页）的容器与切换函数 go(name)。
- 写出像素风的通用组件样式：像素按钮、像素边框卡片、进度条、气泡、标签块。
- 做一个左上角 HUD（头像 + 名字 + 进度 + 三个工具按钮）。
- 字体用 @font-face 占位，颜色用 CSS 变量集中管理。
- 骨架要能跑起来：点按钮可以在这几个空白画面之间来回切。

完成后告诉我每个画面的 id 和用途。
```

### 第 2 段 · 填内容数据

```text
在这个骨架里补上内容配置对象（放在 <script> 最前面，加中文注释）：
- meta：标题、封面文字、日期、HUD 文案
- stages：<N> 个环节，每个包含 编号/图标/主题色/名称/英文标签/人物类型/介绍/要点/信息块
- 其中 <环节 05> 带 gallery（表演者名单），<环节 07> 带 games（游戏列表）
- quiz / gardens / commands：三个小游戏各自的数据
- lawn：封面小人的台词池
- ui：各页面的标题、按钮、提示语

要求：数据与渲染逻辑彻底分开，之后我改内容只动这个配置对象。
```

### 第 3 段 · 画像素美术

```text
现在补像素美术（全部用代码画，不要图片）：
1. 16×16 字符地图图标：<列举需要的图标，例如 话筒 奖杯 对话 人物 音符 剑 相机 奖杯 骰子…>
   用 o=描边 b=主体 a=点缀 的字符矩阵定义，写一个 drawIcon 渲染到 canvas。
2. 32×42 的像素人物立绘 drawFigure(canvas, kind, palette)，支持这些动作：
   <唱歌 跳舞 端杯子 看手机 掷骰子 摆姿势 演讲 站立>。
3. 封面整幅场景 drawScene：天空分层渐变、远近三档建筑、中央主楼（带穹顶/柱子/台阶）、
   树、灌木、白栅栏、花、草坪、前景大树。用固定随机种子保证每次形状一致。
4. 草坪上的小人 actPerson(...)：同一个 32×42 网格缩放到草地尺寸，
   支持走路/敲代码/调机器人/打球/遥控无人机/看书/喝奶茶/看手机/打招呼/聊天。
5. 结语页再加一层飘落的像素粒子。
```

## 三、改造/追加类提示词（在已有页面上继续）

**加一个环节**

```text
在 content/04-stages.json 的 stages 数组里，请在"<某环节>"后面插入一个新环节：
编号用 <09>，名称 <XXX>，图标 <icon 名>，主题色 <#RRGGBB>，
介绍 <一句话>，要点 <2~3 条>，信息块 <时长/形式>。
不要动其它环节，也不要改渲染代码，保持 JSON 格式合法。
```

**改视觉风格**

```text
保持现有结构与交互完全不变，只调整视觉：
改 assets/style.css，把整体配色从"奶油纸张底"换成"<深夜霓虹 / 冬季雪夜 / 复古橄榄绿>",
同步调整 :root 里的颜色变量、按钮渐变、卡片阴影。
注意对比度：正文与背景的对比要够，投屏时不糊。
```

**加交互**

```text
给封面草坪上的小人加两个互动（只改封面，不要影响到其它画面）：
1) 鼠标拖动任意站立的小人，可以把他挪到草坪任意位置；拖动时鼠标显示"抓取"手势；
   拖出画布前要限制范围。
2) 鼠标点击小人（不是拖动的松手），在他头顶弹出一个像素风格的语言气泡，
   显示一句从台词池里随机取的台词，3~4 秒后自动淡出；如果这时继续拖他，气泡跟着移动。
另外：正在来回走动的那两个小人不参与拖动，但可以被点击。
台词池要集中在配置对象里，方便我改。
```

**加/换音效**

```text
把音效函数抽成一个可配置的表：hover / click / open / done / start / boot 各对应一组
"音高序列 + 波形 + 音量"。默认用方波、短促、音量不超过 0.05。
不要引入音频文件，继续用 WebAudio 现场合成。
```

## 四、为什么这样写提示词

| 写法 | 作用 |
| --- | --- |
| 明确「单个 HTML 文件」「不要图片素材」 | 避免 AI 引入外部依赖，产物才好分发 |
| 先给「页面与流程」编号清单 | 让 AI 知道要做几屏、哪一屏是整页、哪一屏是弹窗 |
| 强调「数据与渲染分开」「集中放配置对象」 | 这是后续能轻松改内容的前提 |
| 明确「画布按窗口宽度自适应」「窄屏减少小人」 | 否则很容易只在大屏上好看 |
| 明确「全部用代码画」 | 像素风的关键，AI 一被允许用图片就会跑偏 |
| 最后要「字段说明 + 改哪里对照表」 | 逼 AI 顺手产出文档，省掉你后面摸索 |

## 五、反向提示词（明确不要什么）

```text
不要出现这些：
- 不要用 Tailwind / Bootstrap / React / Vue 等任何框架或 CDN；
- 不要引用任何图片、图标库、音频文件；
- 不要用大面积渐变玻璃拟态、圆角胶囊按钮、投影模糊——那是现代 UI，不是像素风；
- 不要用 window.alert / confirm 之类会中断投屏的原生弹窗；
- 不要把内容写死在 HTML 标签里（后面我要改文案，必须能集中改）；
- 不要只在 1920 宽度下测试，手机竖屏也必须能看。
```
